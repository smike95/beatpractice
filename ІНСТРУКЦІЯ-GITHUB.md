# BeatPractice: як отримати установочні файли через GitHub

Репозиторій містить усе для збірки:

| Тека / файл | Що це |
|---|---|
| `BeatPractice/` | програма (інтерфейс React + оболонка Tauri) |
| `beat-core/` | C++ ядро: звук, аналіз ритму, розділення на партії |
| `.github/workflows/build-windows.yml` | збірка інсталятора Windows (`.exe`) |
| `.github/workflows/build-macos.yml` | збірка двох інсталяторів macOS (`.dmg`: Apple Silicon і Intel) |
| `.github/workflows/mirror-models.yml` | одноразове копіювання нейромереж у власний реліз репозиторію |

GitHub бере віртуальний комп'ютер потрібної системи, збирає ядро, завантажує нейромережі й створює інсталятор, у якому вже є все потрібне.
Користувачу нічого окремо встановлювати не треба.

## 1. Перший раз
1. На https://github.com створіть репозиторій (приватний чи публічний, Actions працює в обох). Нічого не додавайте (ні README, ні `.gitignore`).
2. У теці, де лежать `beat-core`, `BeatPractice` і прихована тека `.github`, виконайте:
```
git init
git add .
git commit -m "first version"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГІН/НАЗВА_РЕПОЗИТОРІЮ.git
git push -u origin main
```
Завантажувати через браузер не раджу: прихована тека `.github` часто губиться.

## 2. Збірка
У репозиторії відкрийте вкладку **Actions**, оберіть потрібний процес, натисніть **Run workflow**:
- **Windows installer**: артефакт `BeatPractice-Windows-installer` (файл `BeatPractice_1.0.0_x64-setup.exe`);
- **macOS installers**: артефакти `BeatPractice-macOS-arm64` (Mac на Apple Silicon, M1 і новіші) та `BeatPractice-macOS-x86_64` (Mac на Intel), файли `BeatPractice_1.0.0_aarch64.dmg` і `BeatPractice_1.0.0_x64.dmg`.

Перша збірка триває 25–50 хвилин, наступні швидші (кешуються Rust і нейромережі). Готові файли лежать унизу сторінки збірки, у розділі **Artifacts**.
Збірка також запускається автоматично, коли ви створюєте мітку версії (`git tag v1.0.0` і `git push --tags`).

**Нейромережі з власного реліза (рекомендовано, один раз).** Запустіть процес **Mirror models**: він скопіює моделі в реліз `models-v1` вашого репозиторію.
Після цього збірки беруть моделі звідти, а якщо їх там немає, із першоджерел.

## 3. Встановлення
**Windows.** Програма встановлюється для всіх користувачів у `C:\Program Files\BeatPractice` (потрібен дозвіл адміністратора).
Інсталятор не підписаний, тому Windows SmartScreen покаже попередження: **Докладніше → Все одно запустити**. Стару збірку спершу видаліть у «Встановлення та видалення програм».

**macOS.** Потрібна macOS 13.3 або новіша. Оберіть `.dmg` за типом процесора (меню  → «Про цей Mac»).
Програма не підписана й не нотаризована, тому macOS каже, що не може перевірити розробника. Для тесту:
- Системні налаштування → Конфіденційність і безпека → «Все одно відкрити» (з'являється після першої спроби запуску), або
- у Терміналі: `xattr -dr com.apple.quarantine /Applications/BeatPractice.app`.

Угода в `.dmg` показується англійською (macOS не показує кирилицю в цьому вікні), повний український текст є у вікні «Про програму».

## 4. Якщо збірка червона
Відкрийте її, натисніть крок з червоним хрестиком і скопіюйте останні десятки рядків журналу.
- **Build core**: помилка компіляції C++ на цій системі.
- **Download models / Download missing models**: тимчасово недоступний сервер із моделями, повторіть запуск (або запустіть Mirror models пізніше).
- **Build installer**: помилка збирання програми.
- **Core smoke test**, **Probe the stem model**, **Collect dependency licenses**: необов'язкові кроки, збірку вони не зупиняють. Probe показує, скільки партій дає модель розділення (очікується 6).

## 5. Оновлення коду
Замініть файли в теці репозиторію новими й виконайте:
```
git add -A
git commit -m "опис змін"
git push
```
Нова версія: змініть номер у трьох місцях (`BeatPractice/package.json`, `BeatPractice/src-tauri/Cargo.toml`, `BeatPractice/src-tauri/tauri.conf.json`).

## 6. Де програма зберігає дані
Результати аналізу й розділення пісень (кеш):
- Windows: `%LOCALAPPDATA%\com.beatpractice.app\cache`
- macOS: `~/Library/Application Support/com.beatpractice.app/cache`

Плейліст і налаштування треків зберігаються в самій програмі. Запуск другої копії програми неможливий: повторний запуск виводить уже відкрите вікно наперед.
